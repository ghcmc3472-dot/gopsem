# 로컬 세션 인수인계 (2026-09-13)

## 프로젝트 목표
AI 이전/이후의 필기시험 준비 패러다임을 바꾸는 **범용 필기시험 AI 학습 코치**.
핵심은 개인별 테스트 → 취약점 분석 → 시험일까지 일별 계획 재조정 루프.

- 대상: 필기시험 전체(범용 구조). MVP는 **법무사 1차**로 시작.
- 입력: 시험 프로필(과목·문항수·합격기준·시험일), 자료(기출문제, 법령 조문, 선택적 교재 PDF/EPUB), 하루 공부 가능 시간.
- 출력: 출제빈도 기반 과목·논점 중요도, 일별 공부자료, 일별 테스트, 다음날 복습 테스트,
  시험일까지의 타임 스케줄, 취약점 리포트, 전략.

## 자료 전략 (제로베이스 기준선)
교재는 나중에. 무료·저작권 부담 없는 공적 자료 세 층으로 시작한다.
1. **기출문제·정답**: 대법원 시험정보(exam.scourt.go.kr) 원본 + 학원 게시판(합격의법학원 24~32회 확인됨).
2. **법령 조문**: 국가법령정보센터(law.go.kr) 오픈 API. 조문 하나 = 지식 노드 하나. 교재 단원 대신 조문을 좌표로 쓴다.
   법무사 1차 과목: 헌법, 민법, 상법, 민사집행법, 부동산등기법, 공탁법, 가족관계등록법, 상업등기법, 비송사건절차법.
3. **판례**: 기출 문항 태깅 중 등장한 판례만 law.go.kr API로 그때그때 수집.

## 로컬 세션에서 할 일 (순서대로)
1. **기출 수집**: `python crawler\crawl_beopmusa_exam.py --kind all` 실행. 대법원 기출 게시판 URL을 브라우저에서 찾아
   `--source scourt --start-url "<URL>"` 로 이전 회차까지 확보. 결과는 `data/beopmusa_gichul/`.
2. **LEXCORE 연동**: 로컬의 LEXCORE 프로젝트(별도 폴더)에 법령 API 키 등이 이미 설정돼 있음. 구조와 환경변수 이름을 파악해서
   이 프로젝트가 같은 키·데이터를 재사용하도록 맞출 것. 키 값은 저장소에 커밋하지 않는다(.env + .gitignore).
3. **프로젝트 골격**: Python 백엔드(pymupdf, Claude API, SQLite) + 단일 HTML 프론트(오늘 할 일 / 테스트 / 취약점 / 일정표).
   AI가 하는 일(문항 추출·조문 태깅·해설·유사문제 생성)과 코드가 하는 일(중요도 계산·일정 배분·간격반복·진도 추적)을 분리.
4. **파이프라인 1단계**: law.go.kr API로 과목별 법령을 조문 단위 JSON으로 수집.
5. **파이프라인 2단계**: 기출 PDF/HWP에서 문항 추출(HWP는 PDF 변환 필요) → 조문 태깅 → 노드별 출제빈도·최근성·배점 중요도.
6. **진단 테스트 → 일정 생성 → 매일 재조정** 로직. MVP는 민법 한 과목으로 끝까지 관통한 뒤 확장.

## 결정된 사항
- 1인용 로컬 도구로 시작, 이후 다중 사용자 확장.
- 학원 자료(총평·해설)는 개인 학습용으로만. 공개 시 공식 문제 + 자체 해설만 사용.
- 교재 전자책은 DRM 때문에 입력 불가. 텍스트 PDF/DRM 없는 EPUB만 지원, 스캔본은 OCR 경로.
