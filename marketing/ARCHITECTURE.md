# 소상공인 F&B 실사 시스템 — 기술 설계서

로컬 세션에서 구축할 매장 진단 파이프라인의 구조, 데이터 소스별 접근 가능성, 구축 순서.
전략 프레임(6단 퍼널·손익 산술·오븐 타임)은 `saltbread-90day-plan.html` 참조.

---

## 0. 한 줄 결론

| 질문 | 답 |
|---|---|
| 네이버 플레이스를 "붙일" 수 있나 | **API 없음.** 사장에게 스마트플레이스 관리자 권한을 위임받는 것이 유일한 정식 경로. 스크래핑은 약관 위반이라 제외 |
| Meta(인스타) API 붙일 수 있나 | 가능. 앱 심사 없이 **개발 모드 + 사장 계정을 테스터로 등록**하면 인사이트 읽기 가능 |
| 유동인구까지 되나 | **서울은 공식 API로 정량화 가능.** 서울 밖은 대리지표(역 승하차·상주인구) + 소진공 상권정보시스템 수동 조회 |
| 업종·메뉴·주변 환경·경쟁점 | 전국 자동화 가능 (카카오 로컬 + 소진공 상가정보, 무료) |
| 노출 진단 | 가능. 핵심 산식은 **검색량(네이버 광고 API) 대비 플레이스 조회수(스마트플레이스)** |

제안서의 "현재 뭐가 잘못됐나" 절반은 API가 아니라 **사장 내부 숫자**(객단가·원가율·폐기율·시간대별 판매)에서 나온다. 이건 API로 못 얻으므로 수집 양식으로 받는다.

## 2. 노출 진단 산식

제안서에 "노출이 어떻게 되고 있는가"를 숫자로 넣기 위한 핵심 계산.

```
시장 규모      = Σ 관련 키워드 월간 검색량        (검색광고 API)
                 예: "성수 소금빵" + "성수 빵집" + "성수동 베이커리" …

노출 점유율    = 플레이스 월 조회수 ÷ 시장 규모   (스마트플레이스 ÷ 검색광고)

의향 전환율    = (길찾기 + 저장 + 전화) ÷ 조회수  (스마트플레이스)

상위 노출 키워드 = 지역검색 API top5 에 매장이 포함되는 키워드 목록
```

| 판정 | 해석 | 퍼널 병목 |
|---|---|---|
| 시장 규모 작음 | 검색 수요 자체가 없음 → 검색 최적화 무의미, 동선·간판·인스타 발견 우선 | 1단계지만 처방이 다름 |
| 시장 큼 · 점유율 낮음 | 수요는 있는데 우리가 안 보임 → 플레이스 정보·키워드·리뷰 | 1단계 |
| 점유율 정상 · 의향 전환 낮음 | 보이는데 안 끌림 → 대표사진·최근 리뷰·가격 노출 | 2단계 |
| 의향 전환 정상 · 객수 정체 | 오려다 못 옴 → 동선·주차·영업시간 | 3단계 |

이 표 하나가 "현재 마케팅이 뭐가 잘못됐나"의 정량 근거가 된다.

## 3. 상권 분석 산식

| 지표 | 계산 | 소스 |
|---|---|---|
| 경쟁 밀도 | 반경 500m 내 카페·베이커리 수 ÷ 반경 내 유동인구 | 카카오 로컬 + 상권 API |
| 거리 가중 경쟁 압력 | Σ (1 ÷ 거리) × 경쟁점 규모 추정 | 카카오 로컬 |
| 수요 시간 프로파일 | 시간대별 유동 (서울: 길단위인구, 외: 역 승하차) | 상권 API / 교통 데이터 |
| 상주 vs 직장 비율 | 직장인구 ÷ 상주인구 | 상권 API (서울) / 주민등록 + 사업체 통계 |
| 카테고리 추정매출 | 상권 내 제과점 업종 추정매출 (서울) | 상권 API |

**수요 시간 프로파일이 오븐 타임 설계의 직접 입력값이다.** 유동이 08시·12시·18시에 몰리면 오븐 타임을 거기에 맞추고, 그 시간대 판매 데이터가 다시 폐기율 계산으로 돌아온다.

## 5. 구축 순서

| 단계 | 내용 | 소요 | 사장 협조 |
|---|---|---|---|
| **0. 이관** | `git pull` → `marketing/` 확보. `.claude/` 스킬·CLAUDE.md 생성. `.env` 준비 | 1시간 | 불필요 |
| **1. 노출·경쟁** | `kakao_local` `naver_local` `naver_datalab` `naver_searchad` → §2 산식 중 시장 규모·상위 노출·경쟁점 | 반나절 | 불필요 |
| **2. 상권** | `sbiz_store` `seoul_trdar` `transit_ridership` `mois_population` → §3 | 1일 | 불필요 |
| **3. 매장 실측** | 스마트플레이스 관리자 위임 + Meta 테스터 등록 → 조회수·유입키워드·인스타 인사이트 | 반나절 + 사장 대기 | **필요** |
| **4. 내부 숫자** | `owner_inputs.yaml` 수집 → 손익분기·폐기 절감 | 사장 면담 1회 | **필요** |
| **5. 리포트** | 제안서 1~3장 자동 생성, 6단 병목 판정, 처방 매핑 | 1일 | 불필요 |

1·2단계는 사장 없이 상호·주소만으로 돌아간다. **첫 미팅 전에 1·2단계를 끝내고 가면** "이 가게의 지금 숫자"로 제안서 1장을 채운 상태로 앉을 수 있다. 3·4단계는 진단 리포트(가격 사다리 1단) 계약 후 진행.

## 6. 한계 명시

- **서울 밖 유동인구는 반자동.** 소진공 상권정보시스템 리포트를 수동으로 뽑고 역 승하차·상주인구로 보강한다. "베스트"는 서울에서만 완전 자동화된다.
- **플레이스 순위는 top5 판정만 자동.** 6위 이하는 로컬 브라우저에서 수동 확인.
- **Meta 인사이트는 사장 계정이 비즈니스/크리에이터일 때만.** 개인 계정이면 전환부터 안내.
- **스마트플레이스 통계는 API가 없어** 사람이 옮겨 적는다. 월 1회 15분 작업.
- **모든 참조 데이터는 현재 시점 값**이라 과거 기간 분석에는 오차가 있다.
